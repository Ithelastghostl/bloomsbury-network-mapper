Architecture and data flow

The platform follows an Observe → Orient → Decide → Act loop. Data flows in one direction: source spreadsheets are ingested into Supabase, enriched by agent workflows, projected into graphs and scores, and surfaced for human decision-making.

Source data

Two Salesforce-exported spreadsheets in Seed_reference/:

FileContentsCount
Friends & SupportersOur core network: donors, strategic contacts, key introducers. Fields: name, funder type, funder sub-type, tier (Priority/Important), affiliation, email, introduced-by.283
HNW Target DonorsHigh-net-worth individuals we want to reach. Same field structure.68

These are parsed into seed-people.json (351 entries) which ships with the app. Each entry carries name, source (supporters/hnw_targets), tier, funder_sub_type, affiliation, and introduced_by. Name matching uses normaliseSeedName() which lowercases, strips honorific prefixes (Sir, Dr, Prof) and trailing honours (CBE, OBE, etc.), and collapses whitespace.

An additional corpus of 20,444 Charity Commission filings (1.6 GB) at MKData/markdown/ provides local evidence for trustee roles, related-party transactions, and charity financial scale.

Graph construction

The social graph is built at render time from three edge sources, merged and deduplicated:

  1. Direct person→person connections from network_connections (CO_DIRECTOR_OF, FAMILY_MEMBER, etc.)
  2. Co-membership: two people linked to the same company in network_connections become an implicit person→person edge. Companies with >50 members are skipped to avoid hairball clusters.
  3. Co-director edges from co_director_edges (Companies House shared boards).

Each resulting edge carries a weight (number of distinct reasons the two people are linked) and a set of provenance labels. Connected components are labelled for cluster colouring.

The 1-hop toggle filters the rendered graph to show only nodes directly connected to at least one supporter (Orbit) or nodes at degree 0-1 (Introduction Graph), stripping out second-order connections for a cleaner view.

Supporter Reach

For each supporter, the graph counts their 1st-degree neighbours who are HNW targets and sums the estimated net worth of all 1st-degree contacts. This produces two metrics per supporter: HNW contact count and network worth. The visualisation sizes bubble nodes by these metrics.

Multi-path introduction routing

The introduction system finds paths from our 283 supporters to every reachable person within 2 hops.

BFS computation

compute-introductions.ts runs a multi-source breadth-first search rooted on all supporters simultaneously:

  • Degree 0 = supporter (our person)
  • Degree 1 = someone a supporter knows directly
  • Degree 2 = someone a degree-1 person knows

The BFS tracks the introducer, the linking organisation (via), and the root supporter for each reached node. Results are stored on attributes.introduction.

Multi-path scoring

compute-multi-paths.ts finds up to 3 distinct introduction paths per target person. For each target, it reverse-walks from the target through the adjacency graph to find all supporter-rooted paths of length 1 or 2, then scores each:

FactorWeightCalculation
Hops40%1-hop = 40pts, 2-hop = 20pts
Shared orgs25%min(1, shared_org_count / 3) × 25. More shared boards or charities between people along the path = stronger bond.
Introducer reach20%min(1, introducer_degree / 15) × 20. A well-connected intermediate person makes a better introducer.
Supporter tier15%Priority = 15pts, Important = 9pts, none = 3pts. Higher-tier supporters are more valuable as introduction roots.

Paths are sorted by score, then the top 3 are picked with a diversity preference: the algorithm prefers different root supporters and different intermediaries before accepting duplicate routes. Each path carries a plain-English reason field explaining why it scores well.

Targets are classified: hnw_target (from the spreadsheet), wealth_identified (has wealth data), or charity_donor (connected to charity-like organisations).

Lead scoring algorithm

The Lead Generator (Decide section) computes a composite score for every non-supporter person:

DimensionWeightFormula
Connectivity20%min(100, connection_count / 20 × 100). Normalised count of network connections. A person with 20+ connections scores 100.
Wealth30%min(100, log10(net_worth) / 9 × 100). Log-scaled so both millionaires and billionaires register, but higher wealth scores proportionally more.
Paths30%min(100, path_count/3 × 50 + best_path_score/100 × 50). Rewards both having multiple routes and having one high-quality route.
Donor affinity20%Base: min(50, charity_overlap × 15) + category bonus (HNW target +40, charity donor +30, wealth identified +20) + philanthropy sector bonus (+10).

Composite = round(connectivity × 0.2 + wealth × 0.3 + paths × 0.3 + affinity × 0.2). The table can be re-sorted by any single dimension by clicking column headers.

When a lead is sent to the Action Backlog, all scoring context travels with it: the composite score, breakdown, best path, root supporter, wealth band, sector, and bio.

Characterisation pipeline

The characterize-connections workflow fills in basic profiles for uncharacterised persons. It runs in parallel batches of 30:

  1. Select: queries Supabase for persons missing profile keys (current_role, employer, sector, wealth_band, etc.), ordered by connection count (most-connected first).
  2. Characterize: one parallel agent per person runs web searches to find their role, employer, sector, location, a one-sentence bio, and a conservative wealth approximation.
  3. Persist: writes profile attributes and upserts wealth_estimates for persons with non-unknown wealth bands.

Wealth approximation during characterisation is conservative: published Rich List figures are used at face value; inferred estimates from strong signals (PE principal, hedge fund founder, major shareholdings) are banded with low confidence (0.3-0.5); no signal results in wealth_band: "unknown".

Wealth augmentation

For deeper research, the augment-people workflow runs a multi-phase pipeline per person:

  1. Research: web search across net-worth databases (Rich Lists, Forbes, Bloomberg), Companies House shareholdings, and local charity filings. The v10 research prompt guides structured extraction.
  2. Anchored search: for supporters, the agent reads their affiliation and "introduced by" from the spreadsheet, then searches with those anchors to disambiguate common names.
  3. Adversarial verify: a separate agent audits whether the net-worth figure is genuinely substantiated by a real, on-topic source URL. Unsourced figures are downgraded to wealth_band: "unknown" (the "source-or-unknown gate").
  4. Persist: writes via storeWealthResult() which inserts enrichment_evidence, upserts wealth_estimates, and stamps wealth_augmented_at.

Wealth bands: 1m_5m (1M-5M), 5m_25m (5M-25M), 25m_100m (25M-100M), 100m_plus (100M+), unknown.

Supporter reach computation

The Supporter Reach view (loadSupporterReach()) computes per-supporter metrics:

  • 1st-degree HNW count: how many of the 68 HNW targets this supporter is directly connected to in the adjacency graph.
  • 1st-degree network worth: sum of estimated_net_worth_gbp (from entity attributes) or band midpoint (from wealth_estimates) for all direct contacts. Band midpoints: 100m_plus = 200M, 25m_100m = 50M, 5m_25m = 12M, 1m_5m = 2.5M.
  • Total reach count: number of unique 1st-degree neighbours.

The graph visualisation sizes bubbles by the selected metric (HNW count or network worth). The table view exposes all metrics sortable.

Stack

  • Next.js 16 (App Router, React Server Components) — pages fetch from Supabase on the server.
  • Supabase Postgres (schema app), service-role client with 8-second timeout and retries.
  • D3.js for force-directed graphs. Layouts are computed synchronously and frozen (nodes settle, then stop).
  • Tailwind CSS with a dark theme (Bloomsbury gold on charcoal).
  • Claude Code workflows for batch characterisation and wealth augmentation — local session, no API keys.
  • Pages are force-dynamic (never prerendered), so the CRM always reflects current data.
