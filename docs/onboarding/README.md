# Onboarding and handoff

Start-to-finish documentation for the Bloomsbury Network Mapper: what it is, how to set it up, how to use it, how it scores, and how to keep it running. Read in the order below, or jump to what you need.

| # | Document | Read it if you want to |
| --- | --- | --- |
| 00 | [What this is](00_WHAT_THIS_IS.md) | Understand the purpose: an intelligence lead generator, the OODA loop, and why the human is required. Read this first. |
| 01 | [User guide](01_USER_GUIDE.md) | Set the project up from scratch (container, Supabase, GitHub, environment) and run it, then learn the basics of using it. |
| 02 | [Scoring and tabs](02_SCORING_AND_TABS.md) | Understand how every score is calculated and why, and what each tab means and is for. |
| 03 | [Analyst playbook](03_ANALYST_PLAYBOOK.md) | Learn the day-to-day workflow: how to work a lead end to end, what good looks like, and the common mistakes. |
| 04 | [Glossary](04_GLOSSARY.md) | Look up a term you do not recognise. |
| 05 | [Data and provenance](05_DATA_AND_PROVENANCE.md) | Know where the data comes from and what is evidenced vs inferred vs estimated, so you trust figures correctly. |
| 06 | [Admin and operations runbook](06_ADMIN_OPS_RUNBOOK.md) | Run and maintain the system: migrations, scripts, re-scoring, flags, deployment. For the maintainer, not the analyst. |

## Quick routes

- **New analyst:** 00 → 01 → 03, with 02 and 04 alongside.
- **New maintainer:** 00 → 01 → 06, with 05 for context.
- **Just want to understand a number on screen:** 02.
- **Just want to trust a figure:** 05.

## The one thing to remember

The platform finds and ranks; a human judges and decides. Every score is a starting point for analysis, not a verdict, and nothing leaves the building without a person choosing it.
